# TVBox PC 0.2.0 点播修正验收

日期：2026-11-05（Asia/Shanghai）。目标是豆瓣选片首页、独立资源浏览和跨资源站自动播放；本轮不增加直播。

## 编译与回归

- Windows x64、AMD Radeon 880M、.NET 9 SDK 9.0.320；便携包带私有 .NET Desktop Runtime 9.0.22。
- Release x64 严格编译要求 0 警告、0 错误。
- 50 项回归断言通过：豆瓣 ID/海报/评分及缺失值、无效推荐拒绝、片名/季数/年份/类型、同集续播与换集清零、电影清晰度标签、HLS 实际媒体、HTML 伪成功拒绝、坏源跳过、三源并发上限、取消后迟到回调、脚本源不误标为已验证、旧数据兼容及豆瓣身份跨进程保存，以及原有字幕/持久化检查。

## 已实际验证

| 场景 | 观察结果 |
| --- | --- |
| 豆瓣首页 | 新数据目录直接显示豆瓣近期热播。电视剧、电影可切换，各返回 20 张首批卡片；有真实评分，无评分显示“暂无评分”。首页没有站点下拉框。 |
| 资源浏览 | 独立资源导航进入原站点目录，保留站点切换、分类和海报列表；点击首页返回豆瓣推荐。 |
| 推荐电视剧自动播放 | 从豆瓣《小城良方》（豆瓣 ID 36675942，2026，8.0 分）卡片点击进入后，无需手选站点即起播第 1 集；后台完成 32 源检查，当次有 18 个来源通过媒体检测。 |
| 推荐电影自动播放 | 从豆瓣《空枪》（豆瓣 ID 37508847，2026，7.2 分）卡片点击进入后，自动找到 U酷来源并实际播放，画面与时间推进正常。来源数随片名和当次网络状态变化。 |
| 手动切源 | 《小城良方》播放中打开来源列表，显示十多个已发现来源；从非凡切到魔都，仍为第 1 集且保留观看位置，实际渲染新来源画面。 |
| 真正的解码失败回退 | 隔离副本首源指向本机测试服务：HLS 和 TS 同步字节通过轻量媒体前缀检查，但缺少可解码音视频。日志先记录首源自动尝试及 avformat_open_input 解码错误，再自动尝试电影天堂；后者成功出画面，记录本次打开的新视频帧。没有由“HTTP 200”直接宣布成功。 |
| 豆瓣身份重启续播 | 重启后仍显示豆瓣首页与电影分类，继续观看显示《空枪》720P 02:08；点击后恢复同一豆瓣 ID、U酷来源和媒体，随后时间推进到 02:57。JSON 同时保留《小城良方》的豆瓣 ID 与最后成功来源。 |
| 来源实时样本审计 | 全部 32 个入口均检查并逐项保存结果。当次有 8 个来源通过《星际穿越》及剧集样本的搜索、HLS 和分片读取；其他来源记录缺片、403、DNS、TLS 或超时，未伪装成全部正常。应用对《小城良方》检测得到 18 个可用候选，与固定旧片样本是不同范围。 |

运行证据位于开发目录 `artifacts/v02-regression.log`、`v02-build.log`、`source-probe.json`、`v02-profile/app.log` 及隔离故障副本的日志；这些运行数据不进入发布包。

## 回归保护与边界

- 新来源必须按本次打开的帧计数增量验证，不能把上一来源累计渲染帧当作新来源成功。
- 失败或尚未渲染的来源不能覆盖最后成功观看进度。剧集切源必须匹配同集；主动选择另一集时从头开始。
- 电影中的 720P/1080P 等清晰度标签不作为集数使用；豆瓣评分不被宣传成片源画质评分。
- 发现任务离页即取消；失败源不会因其他源成功而被清空失败记录后无休止重试。用户手动重新选源可以重新发起一次检查。
- 豆瓣请求失败时使用明确标记的成功缓存或显示可重试错误，不能把资源页偷偷作为首页。
- 旧来源 key、内置订阅地址与用户数据目录保持不变。用户自行选择的配置不被强制覆盖；JAR/Python 仍不支持。

## 限制

- 32 个配置来源不等于每部影片有 32 条可播线路；详情中的状态来自当次检测。影片暂不可用时明确报错，不改播其他季、同名其他年份或电影解说。
- 第三方媒体可能含水印、片内广告或缓冲；个别海报 CDN 暂时失败时会尝试豆瓣提供的另一尺寸，再显示占位图。未承诺任意站点或影片长期有效。
- 已保留字幕、全屏、键鼠、收藏、历史等基础能力；未开展全部来源的长时间稳定性、RTX 5080、4K/HDR 专项验收。
- 旧版首次验收记录保存在 `docs/ACCEPTANCE-0.1.0.md`。本轮对应源码与便携包以 v0.2.0 发布到同一私有下载仓库。
