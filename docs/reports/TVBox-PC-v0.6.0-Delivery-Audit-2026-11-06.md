# TVBox PC 0.6.0 退出排查与包体审计补充

日期：2026-11-06。版本仍为 0.6.0。本次检查维护操作引起的退出、程序包体积及在线交付，不改写此前版本报告中的历史验收事实。

## 最近一次退出的原因与边界

本机日志显示约 21:18:39 启动了维护诊断实例，其后存在用户界面及播放操作。维护脚本约 21:20:52 结束了该实例。同期查询 Windows Application 的 1000、1001、1026、1002 事件，未找到对应的新 TVBox 崩溃记录；CrashDumps 目录未新增本次转储。因此，最近这次退出与维护操作结束进程的时点吻合，不能将其描述为已复现并修复了一个新的客户端崩溃。

维护出错的完整路径：检查运行库时启动完整应用 → 使用了项目不读取的相似环境变量，未充分隔离用户资料 → 用户开始使用该实例 → 维护仅凭 PID 和程序路径判断是测试实例并终止。PID 和启动来源不足以证明仍独占共享桌面上的程序。

已停止该操作，并在项目 `AGENTS.md` 增加两项约束：界面测试必须使用实际的 `TVBOX_PC_DATA_DIR` 并确认独立 QA 目录；不得自动终止共享桌面的交互式 TVBox 实例，包括维护启动后可能被用户接手的实例。仅检查 .NET 宿主时在应用初始化前退出，不打开个人界面。

没有清空、替换或迁移个人收藏、历史、设置、来源或凭据。用户在该实例中的正常操作可能保存了正常的进度或设置，不把这一段冒称为完全隔离的测试。报告不收录个人观看记录、凭据或日志原文。

该结论仅针对最近这次本机退出。不能据此保证其他潜在崩溃不存在；此前的旧版本原生转储也不能当作本次 0.6.0 的新崩溃栈。

## 包体为什么较大

以下来自实际 ZIP 条目压缩大小及原始文件大小统计，单位 MiB（1 MiB = 1,048,576 字节）。

| 版本 | 运行 ZIP | 解压后文件总大小 |
| --- | ---: | ---: |
| 0.4.0 | 207.36 MiB | 526.41 MiB |
| 0.5.0 | 220.25 MiB | 544.22 MiB |
| 0.6.0 | 221.23 MiB | 545.50 MiB |

0.6.0 比 0.5.0 增加约 **0.98 MiB**，主要是报告截图。0.5.0 较 0.4.0 的主要程序依赖变化是 Windows App SDK 升级及 WinUI 文件布局调整；ZIP 压缩方式也影响最终大小，不能把压缩体积变化全部当作新增功能代码。

| 0.6.0 内容 | ZIP 内压缩体积 | 用途 |
| --- | ---: | --- |
| `runtime` | 67.46 MiB | 随包 .NET Core / Desktop 运行库 |
| `libs` | 59.64 MiB | WinUI、托管组件、界面资源及其他依赖 |
| `ffmpeg` | 58.33 MiB | 媒体解析、解码组件 |
| `node` | 33.73 MiB | 已有 JS 来源支持所需引擎 |
| `docs` | 1.39 MiB | 许可、验收、更新报告及截图 |
| `assets` | 0.42 MiB | 图标、配置及资源 |

这些是分发程序文件，不是观看缓存或个人数据。不能通过直接删除运行库、播放器组件或 Node，保证现有功能仍完整可用。本次没有擅自删除依赖或做未经验证的瘦身。

对应源码 ZIP 另为约 94.29 MiB，仅供开发。普通使用只需运行 ZIP，不需要把源码包和解压后的程序目录一起反复下载。
