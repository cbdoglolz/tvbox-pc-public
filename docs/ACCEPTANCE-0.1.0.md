- Windows x64，AMD Radeon 880M；本次没有 RTX 5080 实机。
- .NET SDK 9.0.320；便携包包含私有 .NET Desktop Runtime 9.0.22。
- Release x64 严格编译通过，0 警告、0 错误；宿主全局只有 .NET 6，便携程序仍可独立启动。

## 本次发现并修复

1. 上游首次运行必须输入点播配置：改为包内静态订阅，保留用户后来添加的配置，使用稳定的配置地址和站点 key。
2. 字幕“加载成功”但不可见：FlyleafHost 只提供视频交换链，缺少文本呈现；增加读取解码字幕的 WinUI 覆盖层，并实际核对画面文字。
3. 重启偶尔首页空白：本地配置可能在 Page.Loaded 前完成，旧逻辑漏掉初始化；页面加载时重放尚未完成的初始化，已用最终包复验。
4. 运行时重新打包可能遇到 DLL 占用：在删除旧输出前检查目标目录中的活动进程，拒绝覆盖正在运行的程序。

## 后续回归步骤

1. 执行 `scripts/Build.ps1`，再执行 `python scripts/probe_sources.py`。
2. 全新与已有数据目录各启动一次；首页必须自动出现内容，已有进度必须出现继续观看入口。
3. 加载 `tests/fixtures/acceptance.srt`，必须看到实际字幕文字，加载成功提示不作为通过依据。
4. 播放某剧第 2 集，切到第 3 集，拖动进度后退出重开；核对同一来源、影片、集数、位置。
5. 使用 `scripts/create_source_failure_fixture.py` 创建测试副本，配合独立的 `TVBOX_PC_DATA_DIR` 检查首源失败切换；退出副本后用 `--all-unavailable` 检查全部源失败。此脚本只修改隔离副本，不修改交付包。
6. 执行 `python scripts/verify_package.py`，确认 ZIP 没有用户数据且包含最新程序集与默认配置。

## 已知限制

- 第三方采集视频可能有水印、片内广告或不稳定缓冲，首版没有宣称它们是无广告原画。部分来源海报暂时无法下载时显示占位图。
- 电影某次续播出现过 8 秒定位超时日志，随后画面和进度恢复；没有完成所有来源的长时间稳定性测试。
- 小雅/G-Box/AList/WebDAV、AI、跨端同步、复杂 Spider、新的画质评分与 RTX 5080/4K/HDR 专项验收属于后续阶段。
- 未公开发布 GitHub Release，未生成或安装 MSI，未做代码签名。本次交付本地可运行便携包及完整源码。
