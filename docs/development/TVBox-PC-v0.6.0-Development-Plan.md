# TVBox PC v0.6.0 开发计划：界面与交互改版

日期：2026-11-06。状态：开发计划，尚未实施、编译或验收本版本。

基线：当前仓库 `e2aca03`，程序版本 0.5.0。计划输入为《TVBox PC — UI/UX 全面改版设计规范（Codex 实施版）》v1.0，以及全部 8 张参考图。本文件不表示 0.6.0 已完成或已发布；没有提升当前程序版本。

## 1. 版本目标与范围

让首页、频道、分类、详情和播放器形成统一的桌面影视应用体验。第一步建立主题、组件和页面状态基础，再逐页替换界面。

本版完成：全局主题与导航、新首页、频道二级菜单、分类与高级筛选、三状态排序、完整详情页、海报操作、播放器及收藏/历史/搜索/设置的视觉统一。

沿用当前 C# / WinUI 3 / Flyleaf / FFmpeg 技术栈和已有播放链路。背景播放、优先续接上次成功源、失败换源、手动选源、字幕、选集和进度保护均列入回归门槛。

本版不增加小雅、G-Box、云盘登录、NAS、AI、直播、同步或解码增强。高清资源入口明确展示未接入状态；不会用无效按钮、演示资源或普通源搜索冒充云盘接入。普通来源仍保留现有速度优先/高清优先选择，与未来“搜索高清云盘版本”分开说明。

## 3. 已确定的产品规则

1. **点击海报主体默认直接播放；点击片名、信息按钮进入详情。** 设置可改成海报先进入详情；播放/详情/收藏操作不得互相冒泡触发。
2. **排序方向只有一个按钮：默认 → 正序 → 逆序 → 默认。** 默认恢复当前栏目规则，保留筛选条件；名称使用中文拼音/拉丁字母排序规则，日期与评分显示方向说明。
3. **参考图与正文冲突时采用正文。** 不照搬图中的方向下拉框、独立 A–Z/Z–A 按钮、普通作品筛选里的 4K/HDR 开关、示例分数、总数或会员状态。
4. 一级导航区分内容类型；二级菜单区分推荐/热门/最新/高分；目录来源与平台标签另列。搜索范围与搜索字段分别选择。
5. 默认主题方向为深海军蓝/近黑紫和克制的紫蓝强调色；浅色主题完整适配。新安装默认深色；升级用户保留原品牌主题行为，提供深色、浅色、随品牌切换选项。显式主题设置优先于品牌变化。
6. 豆瓣、Netflix 使用横向品牌标识。Netflix 当前是标签目录，界面明确说明，不能称为 Netflix 官方实时热播榜。
7. TMDB 入口复用实际目录能力，个人 Key 继续选填。不填不影响普通看片；去设置的提示可永久关闭，不能反复打扰。
8. IMDb 目前没有独立评分/发现服务。已匹配可靠 IMDb ID 时提供资料跳转；未接入发现能力前不开放 IMDb 榜单，不将别家的分数当作 IMDb 分数。缺少评分时卡片为 `-`，详情为“暂无数据”。
9. 资源版本保留多线路；平台 Logo 不代表平台提供当前播放线路。文件大小、码率、HDR 等以真实探测为依据，未知明确标记。

## 4. 实施顺序和阶段门槛

| 阶段 | 开发内容 | 通过标准 |
| --- | --- | --- |
| A：基础与主题 | 统一资源字典、按钮/输入/菜单/提示/卡片样式；全局导航与标题栏；主题设置及兼容迁移；详情导航和返回状态契约 | 深浅主题均可读；窗口拖动、系统按钮和全局搜索正常；浏览页面期间播放会话不中断 |
| B：首页与频道 | 横向品牌入口；紧凑 Hero；继续观看；热播电影/电视剧、动漫、高分模块；各频道二级菜单和“查看更多” | 数据来自真实目录；无历史自动收起继续观看；进入频道和返回均保留状态；原豆瓣/Netflix集合仍可进入和继续加载 |
| C：分类与筛选 | 自适应海报墙和紧凑列表；原地高级筛选抽屉；条件标签；分类内搜索；保存/更新/删除筛选；三状态排序 | 同维度默认 OR、跨维度 AND；默认排序不清条件；搜索不丢关键词；明确已检索页数、范围及是否完整 |
| D：作品详情与卡片 | 完整作品详情页；资料、独立评分与人数、可靠外链、选季/选集、现有线路、相似推荐；统一海报悬停与点击偏好 | 海报默认直接播放；详情动作不误播放；播放能走现有多源/续播路径；返回准确恢复列表；缺少能力时正确降级 |
| E：全应用视觉统一 | 播放器浮层、选集、字幕/音轨/倍速/全屏、视频信息；统一搜索/收藏/历史/资源/设置；轻量切换和焦点反馈 | 原快捷键、手动换源、刷新、收藏和控件显隐继续有效；背景播放、进度与最后成功来源不受影响 |
| F：回归与交付 | 数据兼容、错误与空状态、窗口和性能检查；真实播放验收；新旧截图；便携包、源码、校验和独立 MD 报告 | 按下方验收表逐项记录实际结果；明确未验证内容；不以编译、HTTP 200 或静态截图代替播放验收 |

每阶段保留可运行检查点和截图，列出修改文件、已完成/未完成事项及问题。新详情页和新组件逐步替换旧入口；替换验收前保留旧路径，避免一次性删除旧页面。

## 5. 需要先落实的技术约束

- **页面状态**：按页面、目录来源、频道保存关键词、搜索字段、条件、排序、分页游标、已加载候选、滚动位置及键盘焦点。新详情路由和“正在播放”不能覆盖这些状态；保持 0.5.0 已有重启恢复能力。
- **排序迁移**：现有 `SortAscending` 兼容读入显式升/降序；新增第三种默认状态。缓存键和筛选预设同步迁移，不删除收藏、历史、凭据或原预设。
- **查询正确性**：能力允许时由服务端筛选、排序；其余条件逐页校验，显示“已检索 X 页 / 当前匹配 N 部 / 排序覆盖已检索范围”。新页面不会把当前 20 部当作全库，也不虚构总数。切换查询取消旧请求，旧结果不能回写新页面。
- **搜索能力**：片名、演员、导演等字段根据数据提供方实际能力开放；未支持的字段给出原因，不悄悄当作片名搜索。搜索后继续筛选保留原字段与范围。
- **主题和性能**：使用 WinUI 资源与轻量渐变，页面动效约 150–250ms；减少动画时关闭非必要效果。海报按需加载、虚拟化，避免外层无限 ScrollViewer 破坏网格回收。多栏目分别限量预览，“查看更多”进入可持续加载的频道。
- **元数据**：复用有界并发、缓存和唯一匹配机制；可靠匹配后再补评分/外链。电视剧季、集与整剧身份分开保留。演职员、相似推荐、评分人数、完结状态等按真实返回能力展示。
- **来源身份**：计划不替换现有 32 个普通源及其 key，不改默认配置身份；原 12 个豆瓣/Netflix集合 key 保留。新增的页面栏目与播放源分开登记名称和稳定标识，发布报告逐项说明实际增删改。

## 6. 计划验收

下列是待执行的验收场景，不是已通过测试数量。保留并运行现有回归，新增行为覆盖按最终实现确定断言数。

| 场景 | 需要看到的结果 |
| --- | --- |
| 全新安装与旧数据升级 | 新用户可浏览/看片；旧用户收藏、历史、TMDB凭据、来源key与筛选预设保留；不开Key也可播放 |
| 首页与品牌入口 | Hero、继续观看、推荐行是真数据；各品牌入口对应实际能力；缺图、断网有占位/重试 |
| 海报/详情/收藏点击 | 默认海报播放；片名与信息按钮只进详情；收藏不触发播放；切换点击偏好后行为一致 |
| 三状态排序 | 连点三次完成默认→升序→降序→默认；评分、日期、名称方向正确；默认和变更筛选均不误清条件 |
| 筛选与搜索 | 国家多选、类型、年份、分数等组合正确；清除与重置含义不同；搜索范围/字段独立；保存预设可重用 |
| 分页和返回 | 从20部加载到至少60部，去详情、其他频道、设置和正在播放后返回仍保留列表/位置/条件；关闭重开不退化已有恢复能力 |
| 多源与恢复 | 普通点击不等云盘；先尝试上次成功源，失败按偏好换源；手动列表保留；失败不能污染已保存进度 |
| 真正播放 | 电影、电视剧选集、长进度续播、暂停/拖动、字幕、音轨、倍速和全屏逐项记录；无适用样本时标明未验证 |
| 后台播放 | 实际出画面后去首页、筛选、设置再回正在播放，仍是同一会话并继续前进 |
| 资料真实性 | 缺少IMDb分、未知大小、无可靠外部ID、不完整季集等均正确显示；多个评分不串用 |
| 布局与输入 | 1920×1080、1600×900、1366×768及最小约1100×680检查；补查125%/150%DPI；Tab/Enter/Space、焦点、拖动区正常 |
| 主题、性能与稳定性 | 深/浅/品牌主题、减少动画均有效；同机同条件比较0.5.0滚动、页面切换与内存；重复导航/筛选/退出后复查应用错误事件 |

播放测试前将系统默认输出静音并回读确认，使用隔离测试资料，避免污染个人观看记录。稳定性记录写明运行时长、操作和日志边界，不能承诺永不闪退。

- 更新 0.6.0 验收前确认 `docs/ACCEPTANCE-0.5.0.md` 已归档，保留当前历史记录。发布权限以届时明确授权为准，不因本计划自动发布或更改仓库可见性。
- 每次正式更新仍交付独立 MD 报告；其中“已实现”“已实测”“未做/未验证”分别填写，来源及栏目变更逐项登记。
