# 豆瓣推荐与跨源播放的修正

## v0.1 的偏差

启动直接导航到 VodPage；该页调用某一资源站的 HomeContent / CategoryContent，所以主页事实上是资源站目录。详情和播放会话只包含一个站点的播放线路，失败切换仍局限于该站点，没有从豆瓣条目查找其他资源站。

## 原版已核查的流程

参考 ZxxXinI/tvbox main 中的 `data/DoubanHotRepository.kt`、`data/MovieRepository.kt`、`data/PlaybackHealthRepository.kt` 和 `ui/PlayerScreen.kt`：

- 豆瓣 recent_hot 接口提供推荐、豆瓣 ID、海报、评分和副标题；不是播放地址。
- 点开条目后按片名查询资源站，最多三源并行，详情增量补齐多个来源。
- 优先采用有集数的媒体线路，播放器失败时尝试其他来源，保持集数及进度，允许手动选择。
- 原版公开来源文档列出 32 个站点；各自的状态和片库独立，不保证全部可用。

本项目以独立 C# 实现这些行为，没有复制 Android 源码。电影页使用同系列的 recent_hot/movie 接口，电视剧使用 recent_hot/tv；评分仅显示接口实际返回的值。

## v0.2 数据与播放路径

豆瓣首页 → 点击条目 → 32 个已配置来源（最多三源并行搜索）→ 核对片名、季数、明确年份和类型 → 拉取详情与剧集 → 逐个读取 HLS 列表和实际媒体前缀 → 首个候选立即进入 Flyleaf/FFmpeg → 等待本次打开的新视频帧。

其余来源继续在后台检测并加入手动列表。字节检测通过不等于已经解码播放；解码错误或 20 秒内没有视频帧会继续尝试备用来源。失败来源不覆盖已有的观看位置。停止播放、换片或退出时取消发现任务，迟到结果不能再改变页面。

豆瓣收藏/历史采用稳定豆瓣 ID，另存最后成功的来源、资源 ID、集数和进度；旧站点记录保持兼容。同片不同语言/清晰度标签不当作新的影片，不把另一季或电影解说当作可替代线路。剧集换源找不到同集时跳过，不擅自跳到第 1 集。

首页始终是豆瓣推荐；豆瓣失败时使用明确标注的旧缓存或显示可重试错误，绝不偷偷换成资源站列表。资源站目录只在资源页显示。直播入口在本轮隐藏。

## v0.5 会话、续播与刷新

所有页面的播放请求统一交给独立PlaybackFrame。离开视频只隐藏页面并保存进度，不销毁播放器或停止解码；侧栏“正在播放”返回同一会话。换片和退出才销毁旧会话。

续播先只请求历史中SourceKey对应的来源，并用SourceVodId与保存集数定位。读到媒体、新视频帧且实际位置接近保存进度，才确认成功；失败或超时再按速度/高清偏好检测其余来源。正在定位或尚未出画面时禁止覆盖原进度和成功来源。成功起播后仍可从底部手动列表补充其他来源；后续播放失败也会自动启动备用搜索。

更改偏好先保存设置，播放器顶部显示红叹号；点击旁边刷新才重建选源过程，并跳过“优先上次源”以应用新顺序。当前影片、集数与已确认观看进度保留。
